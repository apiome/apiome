# Apiome 11-2026 RC9

We continue to improve the platform based on your feedback with improvements and new features!

---

## Features/Improvements

- **RC9 begins** — RC8 is complete, and its notes are kept in the **Apiome RC8** release notes. The version on the launcher, in the user menu and on **Help & docs** now names the new release candidate (`RC9`). RC9 is about **Projects** and **Catalog**, with OpenAPI 3.2 / 3.1 and Arazzo 1.1 first
- **Arazzo 1.1 everywhere** — The **Import** dialog accepts Arazzo 1.1 documents and their AsyncAPI sources, the CLI validates each document against the schema for the version it declares, and generated workflows can be written as Arazzo 1.1
- **Arazzo workflows with their API files** — Import a `.zip` (or, with the CLI, a folder) holding an Arazzo workflow and the OpenAPI/AsyncAPI files it calls, and they come in as one workflow with every source resolved; any source that is not found is listed in the import report with the reason
- **See an Arazzo workflow as a flow** — An Arazzo catalog item, and a project whose HEAD revision holds workflows, has a **Workflows** tab: each workflow's steps, inputs and outputs, a step graph of its success and failure paths, and whether each source it calls was found; click a step to open the operation it calls
- **Arazzo changes graded by workflow rules** — `apiome diff`, the diff Action, the publish check and a catalog revision's change report now grade an Arazzo workflow by what its callers depend on: a newly required input, a removed output or source description is breaking; changed parameters, success criteria or `onSuccess` / `onFailure` actions are flagged for review, each with its rule and reason
- **Arazzo exports that explain themselves** — An Arazzo 1.1 step that waits on an event channel (`channelPath`) now imports and exports back unchanged, and the fidelity report on the **Arazzo** card names every difference a round trip finds; Arazzo import and export are checked against official OpenAPI Initiative fixtures and files from Redocly, Spectral and Specmatic
- **Arazzo workflows from the CLI and the API** — `apiome arazzo list` and `apiome arazzo show` read the workflows and steps an Arazzo import stores, with whether each step's operation was found; `apiome arazzo validate` checks a workflow file, or fails a CI job when a stored step did not resolve. The REST API reads one workflow, its steps, or any revision of a catalog item
- **Run an Arazzo workflow against a target** — `apiome arazzo run` (and the REST API) runs a stored workflow step by step against a verification target or a mock: each step's request is built from the workflow inputs and earlier steps' outputs, every success criterion is reported with its expected and actual value, and `goto`, `retry` and `end` actions are followed. Only read-only steps run unless the target allows writes, the run opts in and a fixture names the operation
- **Arazzo: complete, current and visible** — Arazzo 1.0 and 1.1 now work end to end: import a workflow with its API files, read it on the **Workflows** tab or from the CLI, validate it, compare revisions, export it back and run it against a mock or a deployment. **Help & docs** has a new **Arazzo in Apiome** page that shows how the pieces fit
- **OpenAPI exports keep everything** — Export an item imported from OpenAPI 3.0, 3.1 or 3.2 to the same version and it comes back as it was read: callbacks, links, webhooks, `discriminator`, examples, `x-` extensions, `$self`, `itemSchema` and the other constructs are no longer dropped. Exporting to an older version lists each construct that version cannot hold in the loss report. The new **OpenAPI construct matrix** page in **Help & docs** shows the result for every construct and version
- **Bundled, dereferenced or split OpenAPI** — An OpenAPI export's **$ref handling** option writes one bundled file (the default), one file with every `$ref` written out in full, or a `.zip` with one file per path and component that imports back as the same document. A schema that refers to itself is kept as a `$ref` and listed in the fidelity report, or stops the export if you choose **error**. Choose it on the **Options** step, or with `apiome export openapi --refs`
- **Upgrade OpenAPI version** — A version's row menu (and an OpenAPI catalog item's header menu) has **Upgrade OpenAPI version…**: it plans the move from Swagger 2.0 or OpenAPI 3.0 / 3.1 to OpenAPI 3.0, 3.1 or 3.2, lists every change by hop with the ones to **Review** marked, and **Apply as new version** adds the upgraded document as a new version. Also `apiome upgrade` in the CLI.
- **OpenAPI 3.2 in Projects** — A project keeps QUERY and custom methods such as `REPORT`, its tag tree (`parent`, `summary`, `kind`), streaming media types (`itemSchema`) and `in: querystring` parameters. **View spec** now names the version the document declares and lists them under **OpenAPI 3.2.0 constructs**. A 3.1 document holds none of them
- **Overlay manager in Versions** — The **Overlays** tab writes OpenAPI Overlays in the app (**Update**, **Remove**, **Copy** and reusable actions, or the whole document as JSON), previews them with a match count per action and every value before and after with the action that changed it, applies the chain as a new version with **Apply as version**, and opens Export studio with **Export with overlays**
- **External references and cycles** — A **References** tab on **Versions** lists every external `$ref` a revision depends on, with where it is used, when it was last fetched and whether it changed. **Refresh** fetches them and lists what changed, **Pin** accepts a document so later changes stay reported, circular references are listed with their path, and administrators can change the workspace external reference policy (block, fetch, allowlisted hosts) right there
- **OpenAPI 3.2 / 3.1: fidelity and authoring** — OpenAPI 3.2, 3.1, 3.0 and Swagger 2.0 now work end to end: imports keep every construct, each document is checked against its own version's schema, exports are written at any version and bundled, dereferenced or split, and versions can be upgraded, overlaid and checked for external and circular `$ref`s. **Help & docs** has a new **OpenAPI in Apiome** page that shows how the pieces fit
- **Apply lint fixes where the finding is** — In a revision's **Quality & Lint report** on **Versions**, findings with a deterministic fix carry a **Fix** chip and **Apply N deterministic fixes** applies every ready one; in **Lint posture**, a finding's drawer and the bulk bar offer **Apply fix**. Fixes are applied with a reason as a new revision that is linted again, and a finding moves to **Fixed** only once that lint no longer reports it. Breaking and conflicting fixes say why they are not applied, a published revision's fixes are read-only, and MCP endpoint findings say why they have no document to fix.
- **Export reports name every loss** — Exporting an item to another format now lists what the conversion changes: the kind of API it reads back as, each operation or type written under another name, and the source details the target has no field for. GraphQL exports now write every type, ONC RPC exports write structs and number their procedures, and an OpenAPI export keeps a request body marked required
- **Exact scalar types in IDL and schema exports** — ASN.1, Avro, OMG IDL, FlatBuffers, TypeSpec, WSDL and XSD exports now write every scalar as the target's own type, and an OpenAPI `integer` with `format: int64` stays 64-bit (Avro wrote it as `int`). Where a target has no type big enough — Avro's `long` for an unsigned 64-bit value, `double` for a decimal — the fidelity report says so
- **Every export reads back** — AsyncAPI, Protobuf, Connect RPC and ONC RPC exports of an item from another format now import back into Apiome: no more AsyncAPI files that fail validation over another format's metadata or a missing scalar schema, and no more `.proto` files that do not compile. ASN.1, WADL, CDDL, FlatBuffers, XSD and RAML are greyed out, with the reason, for a source they cannot hold anything of, instead of exporting an empty file.
- **OpenAPI 3.2 and Arazzo read the same in the catalog** — An OpenAPI 3.2 or Arazzo item in the **Catalog** (from a connector sync, an Arazzo `.zip` or an OpenAPI item before **Convert to Project**) now reads streaming `itemSchema` bodies, QUERY and custom methods, the tag tree and `$self` references exactly as a Project does. A method declared twice imports once, a broken tag `parent` is reported, and a `$ref` into another file is no longer mistaken for a schema of the same name
- **Every export is checked** — CloudEvents, XML-RPC, Connect RPC, Kafka Connect, MCP and A2A exports are now validated before you download them: CloudEvents against the CloudEvents 1.0 rules, XML-RPC with Python's own XML-RPC reader, Connect RPC with `buf build`, MCP and A2A against their schemas, and each file must import back. Where no check exists, the **Validation** tab and the verdict banner in **Export studio** say **Not validated** instead of reading as a pass
- **Import and export fidelity** — Converting an item to another format is now honest end to end: the fidelity report names every loss, scalars are written as the target's own types, every exported file imports back or the target is greyed out with the reason, and every export is checked before download or says **Not validated**. **Help & docs** has a new **Import and export fidelity** page that shows how the pieces fit
- **Catalog and Projects, walked end to end** — **New version** no longer opens on a *Couldn't load this project's branches* error. An OpenAPI file pasted into **Import to catalog** now says to use **Import** on the Projects page and links there, instead of leaving **Continue** disabled with no reason. The import quality step links each finding to its rule in the docs, **Edit project** shows its dates on one line, the **Convert** dialog names the source format ("RAML", not "raml"), and a catalog item no longer logs an error while it loads
- **Catalog and Projects cleanup** — The Bring in, Build and Ship pages now match the code, an OpenAPI 3.2 or Arazzo document reads the same in the **Catalog** as in a Project, and the journey from import to export was walked end to end with seven defects fixed. **Help & docs** has a new **Catalog and Projects** page that shows where an import lands and how the two paths fit
- **Arazzo and Overlay governance** — Arazzo workflows and OpenAPI Overlays are now linted, fixed, graded by a maturity ladder and exported like the APIs they sit beside. **Help & docs** has a new **Arazzo and Overlay governance** page that shows how the pieces fit
- **Faster comparisons of large versions** — A merge request's or review's **Changes** tab, the merge compatibility check on **Versions** and a published version's changelog now read each version's stored OpenAPI document instead of building it again, so comparing two large versions a second time is quick. The first comparison of a version still builds it, and a long wait now says **Rendering the documents for the first time** instead of just spinning
- **Download and compare the original file** — **Download original** in a version's spec viewer and on a catalog item saves the file the import read, under its original name. **Compare** has a new **Originals** tab: a line-by-line diff of the two imported files beside the semantic diff, quick even for very large files. From the CLI: `apiome versions original`
- **One OpenAPI document everywhere** — **View spec**, **Compare**, a catalog item's **Versions** diff and the **Spec** and **Plain diff** of a review or merge request now show the document the REST server keeps for each version, instead of one built again by the page on every click. Opening a version a second time is quick, two versions with the same document say **Identical documents** without diffing, and a very long diff scrolls without freezing the tab. In **Compare**, the **Originals** tab is now a **Rendered / Original** switch on **Diff View**. The document's title now reads `<project slug> API` and its description is the project's; canvas notes are no longer written into it
- **Document store status in the admin console** — The admin console has a **Document store** page: which store the REST server uses (database, S3-compatible bucket or directory) and its settings, whether it answers, how many objects it holds and when they were last verified. **Test connection** writes, reads back and deletes a probe file. Settings stay in the server's environment and credentials are never shown
- **No more hangs on a stuck database session** — Saving a canvas with groups, moving several classes at once and marking a group's properties read-only each ran as a transaction spread across several database connections, which could leave one of them holding locks and stall every screen that touched the same rows; each now runs on a single connection. The web app and the REST API also stop waiting forever: a query blocked on a lock fails after 30 seconds, an abandoned transaction is ended by the database, and a request that cannot get a database connection fails after 10 seconds with an error instead of hanging. Administrators can tune the limits in **Operating Apiome → Database connections**
- **Keep documents in your own bucket** — A workspace can now keep its imported originals and rendered documents in an S3-compatible bucket it owns. **Manage** a tenant and open **Document storage**: choose **Your own bucket**, pick or add a storage credential, name the bucket (with its folder, region, endpoint and SSE-S3 or SSE-KMS encryption if you need them), **Test bucket**, then **Save and move documents**. Existing documents move in the background and stay readable throughout; **Delete old copies…** removes what the move left behind. If the bucket stops answering, owners and administrators are notified and specs and diffs keep working. Needs the new **Document storage → Manage** permission (Owner and Admin have it), and a platform administrator has to turn it on first
- **The document store** — Every import's original and every version's OpenAPI document are now stored once, in the database, a directory or an S3-compatible bucket, and read back instead of rebuilt on every request. Diffs and merge-request **Changes** are faster, **Download original** returns the file you imported, every screen shows the same document, and a workspace can keep its documents in its own bucket. Operators choose the store and watch it on the admin console's **Document store** page
- **Projects, Catalog, OpenAPI and Arazzo** — RC9's core work is complete: the Catalog and Projects agree on every import, OpenAPI 3.2, 3.1, 3.0 and Swagger 2.0 and Arazzo 1.0 and 1.1 work end to end, workflows and overlays are governed like the APIs they sit beside, every export names what it loses, and documents are stored once and read back. **Help & docs** has a new **Projects, Catalog, OpenAPI and Arazzo** page that links the overview page for each part
- **New versions start from your latest** — **New version** now copies the project's head (or the default branch's tip) instead of starting blank, and **Publish** warns before you freeze a version with no operations and no schemas; an empty version's lint report says **Nothing to score** instead of A · 100
