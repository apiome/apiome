More options

One KEY=VALUE per line, stored with the evidence. Never credentials.

Off is a dry run: everything is replayed and reported, nothing is recorded.

They keep the result they have; Run anyway verifies them again.

2Which pacts to verify

  • Each consumer’s latest pact on its main branch4 pacts
  • Pacts of every consumer version deployed or released anywhere5 pacts
  • Pacts on a consumer branch named like this one — feature/credit-notes1 pact

By branch, tag, environment, consumer or “latest”. Duplicates are verified once.

A pact this provider has never passed is reported, not enforced.

Also try pacts from feature branches newer than a date.

The same, from anywhere

apiome pact verify \
  --provider billing-service \
  --provider-app-version 2.7.0+9f31c20 \
  --target staging \
  --branch feature/credit-notes \
  --consumer-version-selector '{"mainBranch":true}' \
  --consumer-version-selector '{"deployedOrReleased":true}' \
  --consumer-version-selector '{"matchingBranch":true}' \
  --enable-pending \
  --skip-already-verified
  • Reads PACT_BROKER_BASE_URL and PACT_BROKER_TOKEN, or the workspace you signed in to with apiome login.

Replace {tenant} with your workspace’s handle in the REST path. In CI, pass the commit as the provider version.

Past runs are on Billing Service’s Verification page.
