Commit statuses

Put the contract verdict on the commit, where the pull request is decided.

On the consumer’s commit
“Pact · Ledger API — awaiting verification”, then verified or failed, on the commit that published the pact.
On the provider’s commit
The verdict of each verification on the provider commit that was verified.
For bi-directional verdicts too
A spec comparison sets its statuses and fires its verification webhooks, as a verification does.

Statuses are written to github.com and gitlab.com repositories registered in the workspace, with the linked account they were registered with. One a switch keeps off is listed as suppressed, with why.

Pipeline recipes

Copy a working pipeline for a consumer and a provider: publish, ask can-i-deploy, and record the deployment.

Save it as .github/workflows/pact.yml.

# .github/workflows/pact.yml
name: pact
on:
  pull_request:
  push:
    branches: [main]
permissions:
  contents: read
  pull-requests: write
jobs:
  pact:
    runs-on: ubuntu-latest
    env:
      PACT_BROKER_BASE_URL: ${{ secrets.PACT_BROKER_BASE_URL }}
      PACT_BROKER_TOKEN: ${{ secrets.PACT_BROKER_TOKEN }}
    steps:
      - uses: actions/checkout@v4
      - run: npm ci && npm run test:pact
      - uses: apiome/apiome/pact-action@main
        with:
          command: publish
      - uses: apiome/apiome/pact-action@main
        with:
          command: can-i-deploy
          pacticipant: Billing Service
          environment: production
          retry-while-unknown: "12"
      - if: github.event_name == 'push'
        run: ./deploy.sh production
      - if: github.event_name == 'push'
        uses: apiome/apiome/pact-action@main
        with:
          command: record-deployment
          pacticipant: Billing Service
          environment: production
