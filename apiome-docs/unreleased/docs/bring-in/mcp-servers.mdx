**MCP servers** catalogs the Model Context Protocol servers your workspace uses: Apiome discovers
each server's tools, resources and prompts, lints them and grades the server. **Go to Bring in → MCP
servers.** Its tabs are **Servers**, **Analytics** (*Preview*), **Capabilities**, **Compare** and
**Agent access**; the middle three appear once you have a server.

This page is about servers *you* bring in. To let an MCP host read *your* published specs, see
[Connect an MCP host](../getting-started/connect-an-mcp-host.mdx).

<Screenshot id="mcp-servers" alt="MCP servers in the dense list view: servers grouped by host with grade, transport and capabilities" />

Search by name, host, URL or category; **Filters** narrows by host, grade, transport, safety,
complexity, protocol, health, visibility, auth and category. Sort by grade (the default), name,
last discovered, capabilities or health, and switch between **Grid** and **Dense list**.

<Screenshot id="mcp-servers-grid" alt="MCP servers in the grid view, with filters, saved searches and collections" />

## Add an MCP server

The steps are **Connect → Discover capabilities → Lint & grade**. To try it on the local stack, use
Apiome's own MCP server.

1. **Click “Add MCP server”.**
2. Enter the **Endpoint URL** — `http://localhost:8765/mcp` on the local stack — and, optionally, a
   **Display name** (`Apiome specs`).
3. Choose the **Transport**: **Streamable HTTP** (the default; right for the example),
   **Server-Sent Events (SSE)** or **Standard I/O (stdio)**.
4. Choose the **Auth type**: **None (anonymous)**, **Bearer token**, **Custom header** or **OAuth
   2.1 access token**. Secrets are stored encrypted and never shown again.
5. **Click “Discover →”.** When it finishes, the dialog says the server is cataloged — **click “View
   endpoint”**.

If discovery fails, read the reason, then **“Discard”** or **“Add this server anyway”**.

## Servers from a registry

An [MCP registry connector](./connectors.mdx#mcp-registry) keeps servers from an upstream
registry — the official registry, Azure API Center, a Kong registry or another Apiome workspace — in
your catalog. **Go to Bring in → Connectors**, click **Add connector** and choose **MCP registry**.

Each server the registry lists with a reachable `streamable-http` or `sse` remote is added here,
private and unpublished, and discovered, linted and graded like a server you added by hand. You can
tell it apart by its source:

- **Added via** reads **Imported from a registry** (`added_via: registry` in the API), and its
  discovery runs are labelled **Registry refresh**.
- **Sources** lists what the registry declared, each with the provenance **registry published**
  and the connector that linked it: the registry entry (`io.github.acme/weather`), the repository,
  and the npm, PyPI, NuGet, Cargo or OCI packages. A package is pinned only when the registry names
  an exact version.

Each sync refreshes the server's name, URL, transport and description from the registry, and retires
a source link the registry no longer lists. Links you added yourself stay. A server that only ships
packages, or whose remote resolves to a private address, is not added. A server whose remote does not
answer is added, but its row on the connector stays **discovered** until it does. The connector's
**Items** tab says why.

## With the CLI or the API

- CLI: `apiome mcp register --name "Apiome specs" --url http://localhost:8765/mcp`, `apiome mcp
  list|show|discover|lint|conformance` — see the [CLI quick-start](../reference/cli-quickstart.md).
- REST: `GET` / `POST /v1/mcp/{tenant}/endpoints`, `POST …/endpoints/{endpoint}/discover`,
  `GET …/endpoints/{endpoint}/versions`, `GET /v1/mcp/{tenant}/browse`,
  `GET /v1/mcp/{tenant}/capabilities`, `GET /v1/mcp/lint/rules` — see the [API
  reference](../reference/api-reference.md).

## Registry API

Gateways and MCP hosts that discover servers through the official MCP Registry API can read your
catalog directly. Point them at your tenant's registry base URL (the full guide is
[MCP registry endpoint](../ship/mcp-registry.mdx)):

```text
https://<your-apiome-host>/registry/mcp/<tenant>/v0.1/servers
```

The same routes also answer under `/v1/tenants/<tenant>/mcp-registry/v0.1/servers`.

- **Publish lists it.** **Publish** a server and make it **Public** and it is listed in the registry
  endpoint for anyone. Send an MCP API key (`Authorization: Bearer …`), a workspace API key
  (`X-API-Key`) or a signed-in session of the same tenant to list private and unpublished servers
  too. A credential that is wrong or belongs to another tenant is refused (`401` / `403`). It never
  falls back to the public list.
- **Names.** Each server is named `apiome.<tenant>/<server-slug>`, for example
  `apiome.acme/weather`. Its `version` is the version the server reports (`serverInfo.version`),
  or the snapshot label when it reports none.
- **Paging.** Up to 100 servers a page (`limit`, default 30). Pass `metadata.nextCursor` back as
  `cursor` to get the next page. Cursors stay valid when servers are added. Filter with `search`
  (name or slug) and `updated_since`.
- **One server.** `GET …/servers/apiome.acme%2Fweather/versions/latest` returns one entry with an
  `ETag`. A client that sends it back in `If-None-Match` gets `304` until the server changes.
- **Packages and repository.** The server's linked sources fill `packages` (npm, PyPI, NuGet and
  other packages, and container images as `oci`) and `repository` (the newest linked git repo). A
  server with no linked source has `packages: []`.
- **Apiome extras.** Each entry's `_meta` carries `dev.apiome/catalog`: the server's grade and
  score, its trust posture (`score`, `grade`, `gatePassed`), the latest lint gate verdict, the owner
  team, whether any source is linked (`sources`: `linked` or `none`), its visibility and its
  manifest digest.
- **Remotes.** A server's URL is listed without any credentials, query string or fragment it was
  registered with. A `stdio` server has no remote.
- **Schema version.** `GET …/v0.1/schema` names the registry API and `server.json` schema versions
  served.

From the CLI, `apiome mcp registry list [--since 2026-10-01T00:00:00Z]` walks every page. The routes
are on the [MCP registry](../reference/rest/mcp-registry.md) REST reference page.
