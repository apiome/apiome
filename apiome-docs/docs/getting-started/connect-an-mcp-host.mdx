Apiome's **MCP server** gives MCP hosts — Claude Desktop, IDEs, agents — read-only access to your
published specs. Every request needs an **MCP API key**: it reads the public specs and the private
specs of its tenant. Without one the server refuses to list or call its tools.

## Create an MCP API key

You need to be an administrator of the tenant.

1. **Go to Workspace → API keys**.
2. **Click “Create MCP key”** (beside **Create API key**).
3. Enter a **Label** (for example `Claude Desktop`) and **click “Create MCP key”**.
4. **Copy the key now** — it is shown only once.

An MCP key is not a REST API key: a key whose **Type** is **REST API** is refused with *Invalid or
unknown MCP API key*. If a key's secret leaks or is lost, [regenerate](../workspace/api-keys.mdx#regenerate-a-key)
it — the host needs only the new secret; the key's tools stay the same. See [MCP keys](../workspace/api-keys.mdx#mcp-keys).

## Point your host at Apiome

The local stack serves MCP at `http://localhost:8765/mcp`. In your host's MCP settings, add a
**Streamable HTTP** server with that URL and the key as a bearer token, sent on every request:

```
URL:     http://localhost:8765/mcp
Header:  Authorization: Bearer <your-mcp-api-key>
```

Without the header the host connects but cannot list tools: the server answers *MCP API key
required*.

Hosts that only speak stdio set the key in `APIOME_MCP_API_KEY` instead — see the [MCP
quick-start](../reference/mcp-quickstart.md) for that and the full set of options.

## Check it works

1. Restart the host so it picks up the server.
2. Ask it to list Apiome's specs — it calls `spec.list`, which includes the seeded `petstore-sample`
   and anything you published.

If a tool answers `capability_disabled`, a tenant administrator has to switch it on: **Manage
workspaces… → Manage → MCP settings**.
