Apiome is where teams design, govern and ship APIs. One path — the **spine** — runs through the
whole product:

> import a spec → edit a class and a path → lint → cut a version → publish → browse → export with the
> CLI → query with MCP

This guide is organised by the job you are doing, in the same order as the product's navigation rail:

| Group | What it covers |
| --- | --- |
| [Build](/build) | Projects, versions, primitives and types, the Studio editor |
| [Bring in](/bring-in) | The catalog, the import wizard, repositories and MCP servers |
| [Ship](/ship) | Publishing, the sunset timeline, the export studio, SDKs and mocks |
| [Govern](/govern) | Style guides, lint posture, the access audit and reviews |
| [Workspace & account](/workspace) | Members, roles, API keys, tenants, your profile and preferences |
| [Admin & tools](/admin) | The admin console, the data browser and migrations |
| [Reference](/reference) | REST, CLI and MCP reference, the mock runtime and CI actions |
| [Release notes](/release-notes) | What changed in each release |
