Govern keeps a portfolio of APIs consistent and accountable: **style guides** and their rules, the
**lint posture** across projects, **reviews**, the **access audit**, the **dependency graph** and
the **shadow APIs** your gateways serve but the catalog does not describe.

Start with [Style guides](./style-guides.mdx) — the rules every spec is scored against and the
policy applied to the result. Then work through findings on [Lint posture](./lint-posture.mdx), set
the levels a guide's APIs climb with [Maturity ladders](./maturity-ladders.mdx), require approvals
with [Reviews](./reviews.mdx), find undescribed APIs with Shadow APIs, see what
depends on what in the [Dependency graph](/reference/rest/graph), read the facts each entity
carries for [Scorecards](./scorecards.mdx), learn what the [usage index](./runtime-usage.mdx) keeps
about live traffic, read who was given or used access in the [Access audit](./access-audit.mdx),
and see how [breaking changes are graded across formats](./breaking-changes-across-formats.mdx).

The rules themselves are documented under [Build](/build) —
[Built-in lint rules](../build/lint-rules.md) and [Custom lint rules](../build/custom-rules.md); this
group also covers [style-guide history](./style-guide-revisions.md) and the rule catalogs for MCP servers.
