A **pacticipant** is an application that takes part in a pact, as a consumer, a provider or both.
The **Pacticipants** page lists every pacticipant in your workspace. Open one to see its versions,
branches, tags, labels, and what each environment runs. For the terms, see
[Pacticipants and versions](./concepts.mdx).

You can also set one up before its first pact, edit its name, display name, main branch, repository,
owner, linked project and labels, and delete it. See [Manage a pacticipant](#manage-a-pacticipant).

## Before you start

- You hold **Pacts** → **View**. Without it, the page shows **Permission denied**.
- Pacticipants appear once a consumer [publishes a pact](./publish-pacts.mdx). Publishing registers
  both the consumer and the provider.

## Open the Pacticipants page

1. In the rail, under **Ship**, click **Contracts**.
2. Click the **Pacticipants** tab. It lists the pacticipants by handle.

Each row shows:

| Column | What it shows |
| --- | --- |
| **Pacticipant** | The display name, which links to the pacticipant's page, and the handle under it. |
| **Main branch** | The branch a query reads when it names none. |
| **Labels** | The pacticipant's [labels](./retention.mdx#label-pacticipants). |
| **Repository** | The repository URL. An `http` or `https` URL opens in a new tab. |
| **Updated** | When the pacticipant last changed, in UTC. |

<Screenshot id="pact-pacticipants" alt="The Pacticipants page: Billing Service, Ledger API and Mobile App, each with its handle, main branch, labels, repository and last update, under a Label filter."/>

Click **New pacticipant** to set one up before it publishes. See
[Create a pacticipant](#create-a-pacticipant). The Contracts tabs open the [**Matrix**](./matrix.mdx),
[**Can I deploy?**](./can-i-deploy.mdx#check-in-the-console),
[**Webhooks**](./webhooks-console.mdx), [**Environments**](./environments-dashboard.mdx),
[**Contract health**](./contract-health.mdx) and [**Verification settings**](./stale-pacts.mdx) pages.

To see only some pacticipants, choose a label from the **Label** list. Choose **Deleted (can be
restored)** from the **Show** list to see the deleted ones. See
[Restore a deleted pacticipant](#restore-a-deleted-pacticipant). Choose **All labels** to see
every pacticipant again. The list shows 50 pacticipants at a time. Click **Load more** to see the
next 50.

If the workspace has no pacticipant yet, the page shows the command that publishes your first pacts:

```bash
apiome pact publish ./pacts \
  --consumer-app-version "$GIT_COMMIT" \
  --branch "$GIT_BRANCH"
```

## Open a pacticipant

Click a pacticipant's name. Its page has two tabs: **Overview** and **Settings**. See
[Manage a pacticipant](#manage-a-pacticipant) for **Settings**. **Overview** has six sections:

- **Overview** shows the handle, the main branch, the repository, the labels, what the pacticipant is
  **Bound to** (a project, a consumer, or nothing), and when it was registered.
- **Owner** shows the team that owns the pacticipant. See [Give a pacticipant an owner](#give-a-pacticipant-an-owner).
- **Branches** lists each branch with its **Head version**, the latest version recorded on it. The
  main branch is marked **Main**.
- **Environments** lists every environment of the workspace. For each one, it shows the versions of
  this pacticipant that are **Deployed now**, with their application instance, and the releases that
  are **Released and supported**. A production environment is marked **Production**. Click an
  environment to open [its page](./environments-dashboard.mdx#read-an-environment).
- **Pacts** lists every pact this pacticipant is in, as the consumer or the provider. Each row shows
  the consumer and provider, this pacticipant's **Role**, the **Latest consumer version** that
  published the pact, when it was published, and how its latest verification went. Click a pact to
  open it. See [Pact detail](./pact-detail.mdx). Click **Network diagram** to see every pacticipant
  connected to this one, with each integration's verdict. See [Integration network](./network.mdx).
  When this pacticipant is the provider of a pact, click **Verification** to see its verification
  results, re-run a pact and verify the stale ones. See
  [Verification results and re-runs](./verification-console.mdx).
- **Versions** lists the recorded versions, latest first, with their branches, tags, when they were
  recorded and by whom, and a link to the build.

<Screenshot id="pact-pacticipant-detail" alt="The Billing Service page: Overview facts, the Owner section naming the Billing team, two branches with main marked Main, Production and Staging with the versions deployed and released there, and three pacts with their roles and verdicts."/>

A commit SHA is shortened to its first 12 characters. Hover over it to see the full version number.

### Narrow the versions

1. Click a branch name, in **Branches** or in the **Versions** table, to list only the versions
   recorded on that branch. The first row is the branch's head.
2. Click a tag in the **Versions** table to list only the versions with that tag. The first row is
   the latest version with the tag.
3. Click **Clear** to list every version again.

You can narrow by a branch and a tag at the same time. The count next to **Versions** says what the
list shows, for example `2 versions on branch main, tagged prod`. The list shows 50 versions at a
time. Click **Load more** to see the next 50.

### Give a pacticipant an owner

A pacticipant's owner is a [team](../../workspace/teams.mdx). The team's members get a notification,
and the team's chat channel gets a message, when something about the pacticipant needs attention:

- a pact it consumes has gone stale and a [re-publish request](./stale-pacts.mdx#who-is-told) opens
  or expires;
- a [verification result](./verification-console.mdx#who-is-told-about-a-failure) for a pact it is
  in fails.

To assign or change the owner:

1. Open the pacticipant.
2. Under **Owner**, choose a team from **Choose a team…**.
3. Click **Assign owner** (or **Change owner** when it already has one).

A suggested owner shows a **Confirm** button. Click it to make that team the owner.

From the command line, run `apiome teams assign pacticipant <id> --team <slug>`. The `<id>` is the
pacticipant's `id` from `GET /v1/tenants/{tenant}/pacticipants/{handle}`. A team page lists the
pacticipants it owns under **Pacticipants**.

With no owner team, notices go to the owner of the consumer or project the pacticipant is
**Bound to**, and otherwise to the **Unowned findings** report. See
[Teams → Ownership](../../workspace/teams.mdx#ownership).

### When a section cannot be read

Each section loads on its own. If one cannot be read, it shows the reason and **Try again**, and the
other sections still show. If an environment's lists cannot be read, its row says
**Could not be read** with the reason, and the other environments still show.

If the workspace has no environment yet, **Environments** shows the commands that create one and
record a deployment. See [Environments and deployments](./environments.mdx). If no pact names the
pacticipant yet, **Pacts** shows the `apiome pact publish` command.

## Manage a pacticipant

### Create a pacticipant

Publishing a pact creates its consumer and its provider for you. Create one yourself when you want to
set it up first, for example to give it an owner or a main branch before its first build.

1. On the **Pacticipants** page, click **New pacticipant**.
2. In **Name**, type the name pacts will use, for example `Billing Service`. The dialog shows the
   handle it gets, for example `billing-service`. URLs and CI name it by the handle.
3. Optional: change **Main branch** (it starts as `main`), choose an **Owner** team, and type the
   **Repository** URL.
4. Optional: choose a project from **Start from a project**. The project is linked to the
   pacticipant, so its published versions can become provider contracts. An empty **Name** takes the
   project's name.
5. Click **Create pacticipant**. Its page opens.

If another pacticipant already has the name, the dialog says so under **Name**. If the owner cannot
be set, the pacticipant is still created and the list says why. Set the owner on its **Settings**
tab.

### Change the settings

1. Open the pacticipant and click the **Settings** tab.
2. Under **General**, change any of these:

   | Field | What it does |
   | --- | --- |
   | **Name** | The name pacts use. See [Rename a pacticipant](#rename-a-pacticipant). |
   | **Display name** | What people read when it differs from the name, for example `Billing (EU)`. Pacts never use it. Leave it empty to clear it. |
   | **Main branch** | The branch that "latest on main" selectors read. |
   | **Repository** | An `http` or `https` URL of the source repository. |
   | **Linked project** | The project that describes this pacticipant as a provider. Its published versions can become provider contracts. Choose **None** to unlink it. |
   | **Labels** | Type a label in **Add a label** and press Enter, or click a label's **×** to remove it. |

3. Click **Save changes**. Only the fields you changed are sent. Click **Discard** to put the stored
   values back.

The page says **Saved.** If a label could not be added or removed, it says which one and why. The
other changes are kept.

<Screenshot id="pact-pacticipant-settings" alt="The Settings tab of Billing Service: General with Name, Display name, Main branch, Repository, Linked project and Labels, the Owner section, the Danger zone, and an aside with the handle, previous names and the same settings as an apiome pact command."/>

The **Owner** section is the same as on **Overview**. See
[Give a pacticipant an owner](#give-a-pacticipant-an-owner). The aside shows the handle, when the
pacticipant was registered, its **Previous names**, and **The same, from anywhere**: your changes as
an `apiome pact create-or-update-pacticipant` command, a Pact CLI command and a REST request.

Without **Pacts** → **Edit**, the tab shows the values without inputs.

### Rename a pacticipant

Change **Name** on the **Settings** tab and click **Save changes**.

- The handle does not change, so URLs, CI jobs and links keep working.
- The history stays: versions, branches, pacts and verification results.
- The old name keeps working. A pact published under the old name, or a URL or command that names
  it, still finds this pacticipant. The old name is listed under **Previous names**.

If another pacticipant has the name, or had it before a rename, the tab says
**A pacticipant named … already exists.** under **Name**, and nothing is saved.

### Delete a pacticipant

Deleting a pacticipant hides it with all its versions, pacts, verification results, deployments,
branches and tags. You can restore it until it is purged, after 30 days by default.

1. Open the pacticipant and click the **Settings** tab.
2. Under **Danger zone**, click **Delete *name*…**.
3. Read what goes with it: the number of versions, pacts and verification results, and the providers
   and consumers that lose it. A provider that loses a consumer gets a different can-i-deploy answer.
4. Type the pacticipant's handle to confirm, for example `billing-service`.
5. Optional: type a **Reason**. It is stored with the delete and in the
   [audit trail](../../govern/access-audit.mdx).
6. Click **Delete *name***.

The dialog then offers **Restore *name*** to undo the delete, and **All pacticipants**.

A pacticipant with a version that is deployed or released now cannot be deleted. The dialog names the
versions and says **Record the undeployment first.** See
[Environments and deployments](./environments.mdx).

### Restore a deleted pacticipant

1. On the **Pacticipants** page, choose **Deleted (can be restored)** from the **Show** list. Each
   row shows when it was deleted, by whom and why, and when it is purged.
2. Click **Restore** on the row.

The pacticipant comes back with the versions that were deleted with it. If another pacticipant has
taken its handle since, restoring is refused. Delete or rename that one first.

### From the command line

```bash
# Create a pacticipant, or update the one with this name
apiome pact create-or-update-pacticipant --name "Billing Service" \
  --main-branch main --repository-url https://github.com/acme/billing

# Delete one (refused while a version is deployed or released)
apiome pact delete-pacticipant --name "Billing Service" --reason "retired"
```

`create-or-update-pacticipant` takes `pact-broker create-or-update-pacticipant`'s flags. It never
renames: rename on the **Settings** tab, or with `PATCH /v1/tenants/{tenant}/pacticipants/{handle}`.
See [`apiome pact` commands](./cli.mdx) and the
[Pacticipants API](../../reference/rest/pacticipants.md).

## Who can do what

| Action | Permission |
| --- | --- |
| Open the Pacticipants page and a pacticipant's page | **Pacts** → **View** |
| See a pacticipant's owner and its settings | **Pacts** → **View** |
| Create a pacticipant | **Pacts** → **Create** |
| Change its settings, rename it, add or remove labels | **Pacts** → **Edit** |
| Assign, change, confirm or remove a pacticipant's owner | **Pacts** → **Edit** |
| Delete a pacticipant, or restore a deleted one | **Pacts** → **Delete** (Owner and Admin) |

Every read and write is scoped to your current workspace. Creating, changing, deleting and restoring
a pacticipant is recorded in the audit trail.
