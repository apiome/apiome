A [catalog item](../bring-in/catalog.mdx) keeps the format it was imported in. Exporting it writes a
file in another format — Protobuf from a GraphQL schema, AsyncAPI from an OpenAPI document — and
shows you what the conversion keeps before you download anything. An export never turns the item
into a project; to edit it as OpenAPI, [convert it](../bring-in/convert-to-openapi.md) instead.

| You want | Use | Open it from |
| --- | --- | --- |
| One item in one format, quickly | The **Export** dialog | **⋯ → “Export”** on the item, or **“Export”** on the item's page |
| One item, with options, a verify step and a job you can watch | The [Export studio](./export-studio.mdx) | **⋯ → “Export to another format…”** on the item or its page |
| Several items in one format, in one `.zip` | Bulk export | Tick the items, then **“Export *n*…”** in the bulk bar |
| An export in a script or a pipeline | The CLI | `apiome export <format>` |

All of them use the same targets and the same fidelity check, so a target that is `lossy` in the
dialog is `lossy` in the studio and in the CLI.

## Export one item: the dialog

1. On the [Catalog](../bring-in/catalog.mdx), **open the item's ⋯ menu** and **choose “Export”**
   (or **click “Export”** on the item's page).
2. **Click “Choose target”**, pick a format and read its fidelity badge, then **click “Continue”**.
3. Read what the conversion drops, approximates or invents. Tick the acknowledgement if it asks
   for one.
4. **Click “Export”** (**“Export anyway”** after an acknowledgement), then the **Download** button
   that names the file, or **“Download .zip”**.

<Screenshot id="export-dialog-targets" alt="The Export dialog's target step: format cards with fidelity badges, one greyed out with its reason" />

Each step is described on [Export a spec](./export-a-spec.md#in-the-app-the-export-dialog).
**“Open in Export Studio”** at the foot of the dialog carries your choices into the studio.

## Export one item: the Export studio

1. **Open the item's ⋯ menu** and **choose “Export to another format…”**. The studio opens with the
   item as its source.
2. **2. Target** — pick a format; each card carries its tier for this item. **Click “Continue”.**
3. **3. Options** — change any option, then **click “Continue”**.
4. **4. Overlays** — optionally add [overlay files](../bring-in/overlays.md#apply-overlays-on-export),
   then **click “Continue”**.
5. **5. Verify** — **click “Run verification”**. Fidelity, validation and lint of the emitted file
   run in one pass. Acknowledge a lossy conversion, then **click “Continue to review”**.
6. **6. Review & Generate** — **click “Generate”**, then **“Download .zip”** or the file's
   **Download** button when the job completes.

<Screenshot id="export-studio-source" alt="Export studio on the Source step: Pet Store API, version 1.2.0, ten export targets" />

Opened from **Export studio** in the rail instead, the studio starts at **1. Source**: **click
“Catalog items”**, search, and **click the item**. Every step is described on
[Export studio](./export-studio.mdx).

## Export several items at once

1. On the Catalog, **tick the items** you want, then **click “Export *n*…”** in the bulk bar.
2. **Choose a target.** The list shows the targets the first ticked item can export to.
3. **Click “Generate”.** One job exports every item, each at its latest version.
4. A table lists each item with its outcome: the fidelity tier, or why it failed. An item that
   fails does not stop the others.
5. **Click “Download .zip”.** Each item's files sit in a folder named after the item, and
   `manifest.json` lists every item, including the ones that failed and why.

<Screenshot id="catalog-bulk-export" alt="Export 3 catalog items to OpenAPI 3.1: two completed with their tiers, one failed with its reason" />

One export takes at most 100 items; with more ticked, the first 100 are exported and the dialog
says so. The other limits — jobs running at once, run time, download size and how long a download
is kept — are on [Export a spec](./export-a-spec.md#limits). Every member can export, whatever their
role; see [Who can export](./export-studio.mdx#who-can-export).

## With the CLI

`apiome export <format>` takes a catalog item's id — the last part of the address of the item's
page — exports its latest version unless you add `--version`, and polls the job for you.

```bash
ITEM=0b7c2a4e-5d1f-4e8a-9c3b-2f6d8e1a7b90

# Every target and its tier for this item
apiome export targets --project "$ITEM"

# The item to TypeSpec
apiome export typespec "$ITEM" --out pets.tsp

# The item to TypeSpec and two more formats: one archive, a folder per format
apiome export typespec "$ITEM" --targets json-schema,smithy --out exports/

# Three items to JSON Schema: one archive, a folder per item (ids or slugs, @VERSION optional)
apiome export json-schema --items orders-api,pets-api@1.0.0,events-bus --out exports.zip
```

A lossy or types-only export exits non-zero unless you add `--force`. With `--items`, the command
prints one row per item and exits **7** when the archive was written but some items failed. The
flags are on [Export a spec](./export-a-spec.md#from-the-cli-several-formats-or-several-items), and
the REST requests behind them on
[Export several items in one job](./export-a-spec.md#export-several-items-in-one-job).

## What each target keeps

The dialog, the studio and `apiome export targets` badge every target with a tier worked out for
*your* item:

| Tier | Means |
| --- | --- |
| `lossless` | Carries the source cleanly. |
| `lossy` | Drops or approximates some constructs, but keeps operations or channels. |
| `types-only` | Only the schemas survive; operations and channels are dropped. |

The table below gives each target's tier for four typical sources, so you can see what a format
keeps before you open either screen. Your item's tiers can differ — a source with no constraints
loses none — so check its own badges before you rely on one. How tiers are worked out is in
[Understand export fidelity](./export-fidelity.md). A target whose tool is not installed on your
server is greyed out in the app with the missing tool named, whatever its tier.
