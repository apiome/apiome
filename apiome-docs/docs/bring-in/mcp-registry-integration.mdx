The [official MCP Registry](https://registry.modelcontextprotocol.io) lists public MCP servers, each
described by a `server.json` entry. Apiome reads it as an upstream source: it imports the servers you
choose into your catalog, keeps them in sync with the registry, and can search the registry next to
your own servers. Apiome reads Azure API Center, a Kong MCP registry or another Apiome workspace the
same way, because they all serve the same MCP Registry API (`v0.1`).

<Screenshot id="mcp-servers-import-registry" alt="Add an MCP server, From a registry: the registry URL, a search of io.github.acme, no credential and Keep these servers in sync ticked to re-sync hourly" />

## When to use it

- **Your team's servers are already in a registry.** Import them all at once instead of adding them
  one by one, and they stay up to date as the registry changes.
- **You want to grade public servers before you use them.** Imported servers are discovered, linted
  and graded like a server you added by hand, so you can compare them first.
- **You want to see what exists before you build.** Search your catalog and the registry together,
  and see which registry servers you already have.

## How the pieces fit

- **One client, one API version.** Import, sync and search all read the registry through the same
  client, pinned to `/v0.1/`. The API is still a preview, so unknown fields are kept and older entry
  shapes are read like current ones.
- **A connector per import.** **From a registry** registers an `mcp-registry` connector. It re-syncs
  **hourly**, imports again only the entries that changed, and records every sync on its **Runs** tab.
- **Only reachable remotes become servers.** An entry with a `streamable-http` or `sse` remote becomes
  a private, unpublished server in your catalog. An entry that only ships packages, or whose remote
  resolves to a private address, is listed with the reason instead.
- **The registry name is the identity.** A server's reverse-DNS name is never added twice, and its
  slug follows the whole name, so `io.github.acme/weather` and `com.example/weather` never collide.
- **The registry's status is kept.** A `deprecated` server is refreshed as usual. A `deleted` one is
  kept and marked deleted, not discovered again.
- **Search never hides your results.** Registry matches come after your own, labelled, with the
  servers you already have left out. A slow or failing registry still returns your results.
- **Credentials stay out.** A registry credential is stored encrypted and never shown again. Secret
  header values a registry declares are never stored, and search results carry no credentials.
