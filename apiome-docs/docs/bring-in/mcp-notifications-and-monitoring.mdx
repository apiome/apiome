Once your [MCP servers](./mcp-servers.mdx) are cataloged, Apiome keeps watching them. It tells your
systems when a server's tools, resources or prompts change, checks every few minutes that each server
still answers, and lets you see how the whole catalog and its scheduled re-discovery are doing. This
page maps where each of those lives.

<Screenshot id="mcp-endpoint-versions" alt="An MCP server's page: the header shows its grade and an Up · 99.6% · 118 ms uptime badge, above the version timeline" />

## When to use it

- **Another system must react when a server changes.** A CI job, a chat channel or an agent gateway
  receives a signed webhook the moment a new version is found, with a summary of what changed and how
  serious it is.
- **You need to know a server is reachable before you rely on it.** The uptime badge on its page
  shows the last day at a glance, and the API gives you the history.
- **You run Apiome and want to know the background work is healthy.** Check that scheduled
  re-discovery is running, and see the catalog broken down by grade, health and change frequency.

## How the pieces fit

- **One event per new version.** A discovery — by hand, on schedule or from a registry sync — that
  finds a changed surface creates a version and raises one `mcp.version.created` event. A discovery
  that finds nothing new, or fails, raises none.
- **Webhooks reuse your subscriptions.** Every active push-webhook subscription in the workspace
  receives the event, signed with its secret and retried with backoff; a delivery that keeps failing
  is dead-lettered. A webhook problem never fails the discovery.
- **Events never leak where a server lives.** They name a server by id, name and slug — never its URL
  or credential.
- **Uptime checks are much lighter than discovery.** A check is only the MCP `initialize` handshake,
  every five minutes by default. It never lists or calls tools and never changes how discovery treats
  the server, and it keeps checking a server discovery has paused, so you see it come back.
- **The badge is about the last day.** **Up** needs the latest check to answer and at least 99% of the
  day's checks to have answered; checks are kept for 30 days.
