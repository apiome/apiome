The **catalog** holds specifications in formats that do not map one-to-one to OpenAPI — gRPC,
GraphQL, AsyncAPI, OData, WSDL, Avro, RAML, Smithy, TypeSpec and more. Catalog items keep their
original format: you can search, diff, lint and export them, but not publish them. To publish one,
[convert it to OpenAPI](#convert-to-openapi). OpenAPI and Swagger imports go to
[Projects](../build/projects.mdx) instead.

**Go to Bring in → Catalog.**

<Screenshot id="catalog" alt="The Catalog in Table view: the facts line under the header, then one card with the filters, view chips and items" />

Under the header, one line sums up the catalog: how many items, which formats (as pills), the
average quality, how many were converted to OpenAPI, and how many are active or disabled (and
deleted, when **Show deleted** is on). **Click “Show stats”** to open the full statistics in
place; Apiome remembers the choice in this browser.

## How the catalog works

On your first visit a note above the list explains what catalog items are. **Click “Learn more”**
to read the full explanation, or **“Got it”** to hide the note in this browser. The same
explanation is always one click away: **click “How the catalog works”** in the page description,
or **“Which formats can I import?”** on the first step of the [Import
wizard](./import-wizard.mdx#import-to-catalog).

The **How the catalog works** dialog says three things — catalog items are stored as-is, they are
not publishable until converted, and OpenAPI and Swagger go to Projects — and lists the **Supported
import formats** this deployment can import now. **Click “Supported formats guide”** for the full
list on [Supported formats](./supported-formats.md).

<Screenshot id="catalog-how-it-works" alt="The How the catalog works dialog: three points about catalog items and the supported import formats as pills" />

## Find an item

- **Filter** by text (<Kbd keys="/"/>, which also matches tags), **Formats**, protocol
  (**REST**, **RPC**, **Event**, **Graph**, **Data Schema**, **Agent**), source (**Uploaded
  file**, **Source URL**, **Pasted content**, **Live discovery**), grade, **domain** and
  **tag**. The domain and tag menus list only what your catalog uses, plus **No domain** /
  **No tags** for the items without one — see [Categorize an item](#categorize-an-item).
- **Chips** — **All**, **Active**, **Needs attention**, and **Deleted** once **Show deleted** is on.
- **Sort** by name, created, updated, quality, grade or format; choose the same column again to
  reverse it.
- **Cards** or **Table**, at the end of the filter row; cards can be grouped by protocol. Your
  choices are remembered in this browser.

## Categorize an item

Every catalog item is categorized three ways, and each is a filter on the list:

| Category | Set by | Where it comes from |
| --- | --- | --- |
| **Paradigm** | Apiome | The imported source — REST, RPC, Event, Graph, Data Schema or Agent (the **protocol** filter). It cannot be changed. |
| **Domain** | You | One of the same domains Projects use (Finance, Healthcare, IoT, …), or none. |
| **Tags** | You | Any short labels you like — `payments`, `public`, `team-orders`. |

1. **Click ⋯ → “Categorize…”** on a card or table row — or, on an item's page, **click
   “Categorize…”** (**“Edit categories”** once it has some) under the title.
2. **Choose a Domain**, or **No domain**.
3. **Type a tag and press Enter** (or a comma) to add it; **click its ×** to remove it.
   Tags are stored in lower case; an item can carry up to 20, each up to 64 characters.
4. **Click “Save”.** The card shows the domain and the first three tags; the **domain** and
   **tag** filters list the new values straight away.

<Screenshot id="catalog-categorize" alt="The Categorize dialog: the derived paradigm, a Domain menu and four tags" />

Changing an item's categories needs permission to edit projects. The same categories are
available to the API — see [With the CLI or the API](#with-the-cli-or-the-api).

## An item's page

<Route path="/ade/dashboard/catalog/[id]" />

**Click an item** to open it. The header shows its status, **Quality** and **Lint** scores, and
**“Convert to OpenAPI Project”**, **“Export”** and **“View code”** — plus **“Open in Designer”**
when your workspace has the Designer suite (see [View an item in Designer](#view-an-item-in-designer)).
Eight tabs follow:

| Tab | Shows |
| --- | --- |
| **Overview** | The API surface (services, operations, types, channels), the quality snapshot and the source snapshot. An entity Apiome inferred or synthesized carries a badge, and a **Provenance** filter narrows the entities to one kind — see [Declared, inferred and synthesized](./inference-provenance.mdx). A source that carries its own tests, such as a [SoapUI project](./soapui-import.md), adds a **Declared tests** group |
| **Format details** | The payload's native structure in its own vocabulary — see [Catalog format details](./catalog-format-details.md) |
| **Source & code** | The raw imported source, read-only, with **“Download raw source”** |
| **Provenance** | Where it came from — intake, format detection, normalization and the import job — and, beside it, **Toolchain & routing**: the revision **Fingerprint**, **Publishable** (`false` for every catalog item) and **Routing**, why the import stored it in the catalog |
| **Conversions** | Every conversion to OpenAPI, with its evidence |
| **Lint & score** | The lint score and findings |
| **Test bench** | Validate a payload against one of the item's schemas |
| **Versions** | The item's revisions |

The page address names the open tab — `?tab=lint`, `?tab=versions` and so on, with no `?tab=`
for **Overview** — so you can **copy the address and send it** to land a teammate on the same tab.
Switching tabs updates the address without reloading the page, and does not add a step to the
browser's **Back** button. The tab ids are `overview`, `format`, `source`, `provenance`,
`conversions`, `lint`, `test-bench` and `versions`; an unknown id opens **Overview**.

While the page or a tab is loading, it shows grey placeholders in the shape of what is coming —
the header, the tabs and the tiles — so nothing moves when the content arrives. The list does the
same with placeholder cards and table rows.

## View an item in Designer

When your workspace has the **Designer** suite, **click “Open in Designer”** on an item's page to
open it in [Studio](../build/studio.mdx) — **read-only**. A catalog item is incomplete and cannot
be published, so Designer shows it without any way to change it:

- the header carries a **Catalog item · read-only** badge, and a banner says why nothing can be
  edited, saved or published;
- **Normalized model** shows the same API surface and parsed entities as the **Overview** tab here;
- **Raw source** shows the imported source, read-only, as on the **Source & code** tab.

To edit the item, convert it: **click “Open in Catalog”** in Designer to come back here, then
**“Convert to OpenAPI Project”**. The converted project opens in Designer like any other project.

The button is hidden for a deleted item, and for a workspace without Designer. Designer's address
is `/catalog/{id}`; `?tab=source` opens it on **Raw source**.

## Convert to OpenAPI

1. **Click “Convert to OpenAPI Project”** on the item (or in its **⋯** menu). Apiome analyzes
   what the source can carry onto OpenAPI.
2. Read the **Fidelity** grade and the **Summary** — **What the source provides** and **What
   OpenAPI favors but is missing**. **Projection graph** shows construct by construct how the
   source maps.
3. Optionally fill **Title**, **Version** and **Servers** under **Fill cheap gaps** and **click
   “Apply & recompute preview”**.
4. **Click “Convert”.** For a low-fidelity conversion, first tick **I understand the converted spec
   will be incomplete and want to convert anyway.**

Apiome creates a new OpenAPI project, and the item shows **Converted to OpenAPI project**. The full
explanation of reason codes and evidence is on [Convert a catalog item to
OpenAPI](./convert-to-openapi.md).

**Export to another format…** in the item's menu produces a document in another format instead —
it never creates a project.

## Delete and restore

**Delete item** hides an item; turn on **Show deleted** and choose **Undelete item** to bring it
back. **Permanently delete** asks you to type the item's slug, then **“Delete everything”**.

## Act on several items at once

1. **Tick the checkbox** on each card (or table row) you want. **Select all** above the cards —
   or the header checkbox in Table view — ticks every item the current filters show. Your
   selection is kept when you switch between Cards and Table.
2. A bar appears at the bottom of the page: **“Convert N…”**, **“Delete N”** and
   **“Undelete N”**, each counting the items it applies to (Convert and Delete reach live
   items; Undelete reaches deleted ones).
3. **Click the × on the bar** to clear the selection.

<Screenshot id="catalog-bulk-selection" alt="Three catalog cards ticked, with the bulk bar offering Convert 3… and Delete 3" />

If some items cannot be deleted or undeleted, a message lists **each item and the reason** it was
refused; the rest are done.

### Convert several items

**Click “Convert N…”** to open the review. Apiome previews every item first — the same fidelity
check as [converting one item](#convert-to-openapi) — and lists each with its grade, its
fidelity and its state.

1. **Untick** any item you want to leave out.
2. For each **low fidelity** item, tick **I understand the converted spec will be incomplete and
   want to convert anyway.** When two or more items are low fidelity you can tick **Apply the
   fidelity warning to all …** instead.
3. Optionally **click “Review…”** on an item to open its full preview (summary, projection
   graph, defaults) and convert it from there.
4. **Click “Convert N”.** Items are converted one at a time; each row then shows **Converted**
   (with **Open project**) or **Failed** with the reason. **Click “Convert”** again to retry the
   failed ones, or **“Done”** to close.

## Use the keyboard

Every control on the list and on an item's page works from the keyboard.

- **Tab** moves through the toolbar, the chips, then each card or row: its name (the link),
  its **Quality** and **Lint** scores, and its **⋯** menu.
- On an item's page, **focus a tab** and use <Kbd keys="←"/> / <Kbd keys="→"/>
  to move between tabs, <Kbd keys="Home"/> / <Kbd keys="End"/> for the first and last.
- In the **⋯**, **Sorted by** and **Formats** menus, <Kbd keys="↑"/> / <Kbd keys="↓"/>
  move through the items and wrap at either end, <Kbd keys="Enter"/> chooses one and
  <Kbd keys="Esc"/> closes the menu.
- When you close a dialog — with <Kbd keys="Esc"/>, **Close** or **Cancel** — focus goes back
  to the button or **⋯** menu that opened it.

## With the CLI or the API

- CLI: `apiome import graphql ./01-simple-user.graphql`, `apiome convert <item-id> --to openapi
  --dry-run`, `apiome formats` — see the [CLI quick-start](../reference/cli-quickstart.md).
- REST: `GET /v1/catalog/{tenant}/entities` lists every kind in one shape (`kind`, `id`, `slug`,
  `name`, `description`, `owner`, `updatedAt`, `href`, `graphNode`), filtered by repeatable `kind`,
  `team` and `q` and paged with `cursor` (`pagination.nextCursor`);
  `GET /v1/catalog/{tenant}/entities/summary` returns the count of each kind and the three callouts
  — see [Catalog entities](../reference/rest/catalog-entities.md).
- REST: `GET /v1/catalog/{tenant}` (filter with repeatable `protocol`, `format`, `domain` and
  `tag`; `uncategorized` selects items without a value), `GET /v1/catalog/{tenant}/facets`
  (the count per value), `PUT /v1/catalog/{tenant}/{item}/categories` (`{ "domain", "tags" }`),
  `GET /v1/catalog/{tenant}/{item}`,
  `GET …/{item}/analysis|lint|source`, `POST …/{item}/convert`, `GET …/{item}/conversions` — see the
  [API reference](../reference/api-reference.md).
