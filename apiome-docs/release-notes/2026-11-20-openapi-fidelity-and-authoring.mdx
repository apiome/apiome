OpenAPI 3.2, 3.1, 3.0 and Swagger 2.0 now work end to end in Apiome, from import to export, with
nothing dropped silently. A new [OpenAPI in Apiome](/build/openapi) page shows how the pieces fit.

{/* truncate */}

- **Lossless:** an item imported from OpenAPI 3.0, 3.1 or 3.2 exports back at the same version as
  it was read, callbacks, webhooks, `discriminator`, examples, `x-` extensions and `itemSchema`
  included. The [OpenAPI construct matrix](/reference/openapi-construct-matrix) measures every
  construct on the OpenAPI Initiative's own test documents.
- **Validated:** every document is checked against the official schema for its version: 3.2, 3.1
  (3.1.0, 3.1.1 and 3.1.2), 3.0 and Swagger 2.0. A document no schema covers is reported as **not
  validated**, never as valid.
- **Dialect-aware:** each schema keeps the JSON Schema dialect it was written in, and every rewrite
  between OpenAPI 3.0 schemas and JSON Schema 2020-12 is listed.
- **Your layout:** export bundled, dereferenced or split into one file per path and component;
  circular `$ref`s are kept and reported, never expanded forever.
- **OpenAPI 3.2 in Projects:** QUERY and custom methods, the tag tree, streaming media types and
  `in: querystring` parameters are kept, shown in the spec viewer and written to 3.2 exports.
- **Upgrade, overlay, watch:** **Upgrade OpenAPI version…** moves Swagger 2.0, 3.0 or 3.1 to a newer
  version with every change listed; the **Overlays** tab writes, previews and applies OpenAPI
  Overlays; the **References** tab tracks every external `$ref` and circular reference.

See [OpenAPI in Apiome](/build/openapi).
