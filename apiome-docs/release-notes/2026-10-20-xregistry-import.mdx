Apiome now reads [**CNCF xRegistry**](/bring-in/xregistry-import) documents — the CloudEvents
project's catalog of schemas, message definitions and endpoints — as event-driven APIs in the Catalog.

{/* truncate */}

- **One model for the whole registry.** Schemas become types (Avro, Protobuf and XSD through their own
  importers), each message definition an operation on the channel its CloudEvents `type` names, and
  each endpoint a service with its broker URIs — publish for a producer, subscribe for a consumer.
- **Versions and diffs.** Re-importing an unchanged registry is the same version; a new release
  reports added and removed messages, changed schemas and new endpoints.
- **Live registries too.** The [xRegistry registry crawl](/bring-in/connectors#registry-crawl) now
  imports each message group and endpoint as well as each schema, and the new `include` scope picks
  which of the three to crawl.
- **From the CLI.** `apiome import xregistry ./registry.xreg.json`.
