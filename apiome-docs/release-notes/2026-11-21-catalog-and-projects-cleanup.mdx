Catalog and Projects now agree with each other and with their docs. A new
[Catalog and Projects](/bring-in/catalog-and-projects) page shows where an import lands, how the two
paths agree, and the journey from import to export.

{/* truncate */}

- **Docs that match the code:** the Bring in, Build and Ship pages say Arazzo 1.0 and 1.1, describe
  workflows stored as records, and list formats from the registries, including Arazzo 1.1 and
  Overlay lint.
- **One result from both paths:** an OpenAPI 3.2 or Arazzo document reads the same in the catalog
  as in a Project. See
  [OpenAPI 3.2 and Arazzo read the same in the catalog](/release-notes/catalog-projects-path-parity).
- **The journey, walked end to end:** import, convert, version, publish and export were checked at
  two widths in both themes, and seven defects are fixed. See
  [Catalog and Projects, walked end to end](/release-notes/catalog-projects-usability-audit).
- **REST:** no changes.

See [Catalog and Projects](/bring-in/catalog-and-projects).
