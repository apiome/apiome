The CloudEvents and xRegistry work is complete: the xRegistry document export, the read-only
xRegistry API over your published catalog, their fidelity checks against the official xRegistry
schema, and the target card, CLI and fixtures.
[CloudEvents and xRegistry](/ship/export-a-spec#cloudevents-and-xregistry) brings them together.

{/* truncate */}

- **When to use which:** CloudEvents for a sample event to send or test with, an xRegistry document to
  hand over an event catalog as a file, and the xRegistry API when tools should read your catalog live.
- **At a glance:** the three side by side — what each is made from, what you get, the options, what an
  event and a type become, what checks it, how it imports back, the CLI and where to read more.
