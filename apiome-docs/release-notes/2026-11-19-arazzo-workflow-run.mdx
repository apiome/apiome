An Arazzo workflow can now be run, not only read. `apiome arazzo run` (and a new REST endpoint)
sends a stored workflow's steps in order to a verification target — a deployment, or a mock — and
reports every step with its success criteria, expected against actual.

{/* truncate */}

- **Steps feed each other:** each step's parameters and request body are built from the workflow
  inputs and earlier steps' outputs (`$inputs.…`, `$steps.<id>.outputs.…`, `{$…}` templates).
- **Criteria are assertions:** `simple`, `regex` and `jsonpath` criteria are checked against each
  response; a failing one prints the actual value, such as `'pending' == 'paid'`. A step with no
  criteria must return a `2XX`.
- **Actions are followed:** `end`, `goto` a step, and `retry` with `retryLimit` and `retryAfter`.
- **Read-only by default:** a `POST`, `PUT`, `PATCH` or `DELETE` step is sent only when the target
  allows writes, the run opts in with `--allow-mutating` and a fixture names the operation;
  otherwise nothing is sent and the command exits `3`.
- **Recorded:** every run that starts is stored as verification evidence, one record per step.
- **REST API 1.773.0, OpenAPI 1.604.0; CLI 0.151.0.**

See [Run a workflow against a target](/build/arazzo-workflows#run-a-workflow-against-a-target).
