Apiome now keeps every imported **original** and every **rendered document** as an immutable
object in a [document store](/admin/document-store): an S3-compatible bucket in production, a
directory for development, or the database when nothing is configured. Classes, properties and
paths stay in Postgres, where they are edited. Diffs, downloads, exports and `/v1/schema` read the
stored bytes instead of building the document again on every request.

## What changes for you

- **Faster comparisons.** Both sides of a diff, a merge request's **Changes** tab and a
  compatibility check read stored documents; a version's document is rendered once per change.
- **The file you imported, kept.** **Download original** in a version's spec viewer and on a
  catalog item returns it byte for byte, and **Compare** can diff two originals.
- **One document everywhere.** **View spec**, **Compare**, the catalog's **Versions** diff and the
  review and merge-request spec views show the document the REST server keeps, so they cannot
  disagree.
- **Your own bucket.** A workspace can keep its documents in a bucket it owns, when the
  installation allows it.

## For operators

- Choose the backend with `APIOME_DOCUMENT_STORE` (`db`, `s3` or `filesystem`). An installation
  that sets nothing keeps everything in the database.
- The admin console's **Document store** page shows the backend, its health, usage and the
  tenants on their own bucket, and tests the connection.
- Existing sources and snapshots move into the store with a resumable, verified migration.
- Unused objects are deleted after a grace period, and an integrity check re-hashes stored
  objects on a schedule.
- Docker Compose ships a local MinIO, and a nightly benchmark guards large-spec performance.
